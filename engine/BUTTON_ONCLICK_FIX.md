# Nimbus InModule Button OnClick - Complete Fix Documentation

## Executive Summary

Fixed critical bugs in the Nimbus InModule rendering system that prevented button click handlers from working. The issues affected XML-defined buttons with `onClick` attributes in InModule mode (custom 2D rendering without WPF controls).

### Critical Bugs Fixed:
1. ❌ **onClick attribute ignored** → ✅ Now properly stored and executed
2. ❌ **Unnamed buttons broken** → ✅ Auto-naming system implemented
3. ❌ **No handler execution** → ✅ Connected to LogicRunner via ExecuteHandler()

---

## Bug #1: OnClick Handler Not Wired

### Problem
The `ModuleRenderer.ApplyAttributes()` method had no case for `onclick` attribute:

```csharp
// OLD CODE (ModuleRenderer.cs, line ~1025)
default:
    element.SetProperty(attrName, attrValue);  // onclick silently stored as generic property!
```

**Impact**: 
- onClick attribute was ignored completely
- Buttons with onclick wouldn't respond to clicks
- Silent failure - no error messages

### Root Cause
The massive `switch` statement in `ApplyAttributes()` had ~50+ cases for various attributes (text, background, fontSize, etc.) but NO case for "onclick". The default case just stored it as a generic property that was never used.

### Solution
Added explicit handler for `onclick` and `onmousedown` attributes:

```csharp
// NEW CODE (ModuleRenderer.cs, line ~1023)
case "onclick":
case "onmousedown":
    // Store onclick handler for later execution in ModuleWindow.HandleClick()
    string existingName = element.Id;
    if (string.IsNullOrEmpty(existingName) || existingName.StartsWith("Button_"))
    {
        // Auto-generate a name if button doesn't have one
        existingName = "_nimbus_" + element.ElementType.ToLower() + "_" + Guid.NewGuid().ToString().Substring(0, 8);
        element.Id = existingName;
    }
    
    // Store handler info in Properties for ModuleWindow to access
    element.SetProperty("__onclick__", attrValue);
    element.SetProperty("__elementId__", existingName);
    _engine.Log("MODULE", "OnClick handler registered: " + existingName + " -> " + attrValue);
    break;
```

**Key Points**:
- Handler name stored in `Properties["__onclick__"]`
- Element ID stored in `Properties["__elementId__"]`
- Auto-naming handled here (see Bug #2)
- Proper logging for debugging

## Bug #2: Unnamed Buttons Not Working

### Problem
When a button had `onClick` but no `Name` attribute:
- Multiple unnamed buttons had identical generated IDs
- Hit-testing couldn't distinguish between them
- Click handlers would fire on wrong button

Example:
```xml
<Button Text="Save" onClick="OnSave"/>    <!-- ID auto-generated to "Button_0" -->
<Button Text="Cancel" onClick="OnCancel"/> <!-- ID also auto-generated to "Button_0" -->
<!-- Collision! Both have same ID -->
```

### Root Cause
ModuleRenderer didn't implement auto-naming for buttons without explicit names, unlike WpfUI.cs which had:

```csharp
// WpfUI.cs (lines 335-344) - auto-naming logic
if (string.IsNullOrEmpty(existingName))
{
    if (!string.IsNullOrEmpty(onClick) || !string.IsNullOrEmpty(onRightClick))
    {
        _autoNameIndex++;
        autoGeneratedName = "_nimbus_" + elementName.ToLower() + "_" + _autoNameIndex;
    }
}
```

### Solution
Integrated auto-naming into onclick handler case (see code above):

```csharp
// Auto-generate a name if button doesn't have one
existingName = "_nimbus_" + element.ElementType.ToLower() + "_" + Guid.NewGuid().ToString().Substring(0, 8);
```

**Format**: `_nimbus_{elementtype}_{8-char-guid}`

**Examples**:
- `_nimbus_button_a1b2c3d4`
- `_nimbus_nimbusbutton_f5e6d7c8`
- `_nimbus_iconbutton_12345678`

**Advantages**:
- Globally unique (GUID-based)
- Easy to identify in debug logs
- No collision risk
- Backwards compatible (existing named buttons unaffected)

## Bug #3: Handler Execution Not Connected

### Problem
Even after storing the handler name, ModuleWindow didn't know how to execute it.

The old `HandleClick()` method:
```csharp
if (button.OnClick != null)
{
    button.OnClick();  // Never set because __onclick__ property never checked!
}
```

**Impact**:
- Handler stored but never looked up
- Handler stored but never found in Logic section
- Handler stored but never executed

### Root Cause
The click handler just checked for OnClick delegate, but:
1. Custom UIModule elements don't have OnClick delegate populated
2. No mechanism to convert onclick handler NAME to actual handler execution
3. No integration with WpfEngine.ExecuteHandler()

### Solution
Updated `ModuleWindow.HandleClick()` to check for `__onclick__` property first:

```csharp
// NEW CODE (ModuleWindow.cs, line ~234)
private void HandleClick(Point clickPos)
{
    foreach (var kvp in _clickableRegions)
    {
        if (kvp.Key.Contains(clickPos))
        {
            IUIModule module = kvp.Value;
            
            // FIX #1: Check for __onclick__ handler property (from ModuleRenderer)
            object onclickHandler = module.GetProperty("__onclick__");
            if (onclickHandler != null && !string.IsNullOrEmpty(onclickHandler.ToString()))
            {
                string handlerName = onclickHandler.ToString();
                AddDebugLog("[CLICK] Element clicked with onclick handler: " + handlerName);
                
                try
                {
                    // Execute via WpfEngine.ExecuteHandler (critical fix for InModule mode)
                    _engine.ExecuteHandler(handlerName, module);
                    AddDebugLog("[ACTION] Handler executed: " + handlerName);
                }
                catch (Exception ex)
                {
                    AddDebugLog("[ERROR] Handler execution failed: " + ex.Message);
                }
                
                InvalidateVisual();
                return;
            }
            
            // FIX #2: Fallback to OnClick delegate (for legacy support)
            if (module is CustomUIButton)
            {
                // ... existing code ...
            }
        }
    }
}
```

**Key Points**:
- Check `__onclick__` property FIRST (highest priority)
- Call `_engine.ExecuteHandler()` which:
  - Looks up handler name in `_eventHandlers` dictionary
  - Finds handler XmlNode from `<Logic>` section
  - Calls `LogicRunner.Execute()` to run handler commands
- Fallback to `OnClick` delegate for legacy elements
- Proper error handling and logging

## How It Works End-to-End

### XML Declaration
```xml
<Logic>
    <Handler Name="OnButtonClick">
        <Alert Message="Button was clicked!"/>
    </Handler>
</Logic>

<UI>
    <Button Text="Click Me" onClick="OnButtonClick"/>
    <NimbusButton Text="Modern Button" onClick="OnButtonClick"/>
    <Button Text="Unnamed" onClick="OnButtonClick"/>  <!-- No Name attribute -->
</UI>
```

### Execution Flow

```
1. PARSE & RENDER (ModuleRenderer.RenderUI)
   ├─ Parse Button element
   ├─ Call CreateElement("Button", id) → CustomUIButton instance
   └─ Call ApplyAttributes()
      ├─ case "text": button.Text = "Click Me"
      ├─ case "background": button.Background = "..."
      └─ case "onclick": 
         ├─ Auto-name if missing: _nimbus_button_a1b2c3d4
         ├─ Store handler name: Properties["__onclick__"] = "OnButtonClick"
         └─ Store ID: Properties["__elementId__"] = "_nimbus_button_a1b2c3d4"

2. RENDER CANVAS (DrawingCanvas.RenderModule)
   ├─ Call RenderButton(dc, button, bounds)
   ├─ Draw button visuals
   └─ Register clickable: _clickableRegions[bounds] = button

3. USER CLICKS (DrawingCanvas.MouseDown)
   ├─ Get mouse position
   └─ Call HandleClick(Point clickPos)
      ├─ Find element in _clickableRegions
      ├─ Get "__onclick__" property = "OnButtonClick"
      ├─ Call _engine.ExecuteHandler("OnButtonClick", button)
      │  ├─ Look up handler in _eventHandlers
      │  ├─ Get handler XmlNode
      │  └─ Call _logicRunner.Execute(handlerNode, button)
      │     ├─ Parse handler XML
      │     └─ Execute all commands (Alert, Set, Increment, etc.)
      └─ InvalidateVisual() - redraw UI
```
